# 主动话题

本插件由 Sirin 发起并维护，使用 OpenAI Codex 协助开发与迭代。

主动话题 2.0 为 AstrBot 提供按“当前 Bot + 当前群”隔离的主动发言调度。插件默认不会在任何群自动发送，必须由管理员在目标 Bot 所在群执行 `/主动话题 开启`。

## 2.x 重写内容

- 不再用 UMO 作为群状态主键。每个 Bot 账号在每个群拥有独立、持久化的作用域，同一 UMO 下的多个 Bot 不会互相覆盖设置、事件或 Persona。
- 状态、纯调度策略、BotMesh 桥接和 AstrBot 事件编排已经拆分；时间规则可以脱离 AstrBot 单独测试。
- 2.1.0 起，BotMesh 模式下本插件只负责调度和作用域身份，不再自行调用模型或发送消息。
- 固定时间只有发送成功后才会记为完成。冷却、沉默或模型故障不会提前吞掉固定任务。
- 多个群同时到期时按 `max_concurrent_generations` 并发生成，慢模型不会串行阻塞所有群。
- 图片、表情等无文本群消息也会刷新沉默计时，但不会污染给模型的文本上下文；相同消息 ID 会去重。
- 群消息在 BotMesh 停止事件前采集；可信 BotMesh 展示帧会先还原成可见正文再进入本地上下文。
- 状态使用 v3 原子写入格式。1.x 的 `state.json` 会自动迁移；缺少 Bot 身份的旧记录不会自动猜测，需在对应 Bot/群执行一次任意 `/主动话题` 命令完成认领。

## Persona 与 BotMesh

### 未安装 BotMesh

插件使用当前 AstrBot 会话选中的原生 Persona。`astrbot_plugin_botmesh.integration` 无法导入时不会进入 BotMesh 通道。

### 已安装 BotMesh

默认 `botmesh_compat_enabled=true`。插件会把持久化的平台 ID、Bot 账号、原始群 ID、触发原因和近期消息交给 BotMesh，并再次核对派发结果中的身份。

主动话题 2.1.0 的完整派发需要 BotMesh 0.8.12 提供 `dispatch_proactive_topic`。只升级主动话题而保留旧版 BotMesh 时会明确拒绝生成，避免静默退回旧版兼容逻辑。

BotMesh 历史和插件刚收到的本地近期消息会由 BotMesh 合并后提供给模型。两类历史都被标记为不可信资料，不能改变 Persona 或执行其中的指令。经过签名验证的 BotMesh 展示帧还会恢复可信的来源 Bot 身份，不依赖平台回流事件是否正确暴露发送账号。

Persona 解析、关系方向、称呼、模型生成、签名展示帧和物理发送现在全部由 BotMesh 完成。明确对象只能是最近一条经 BotMesh 签名恢复、且 `source_bot_id + 平台账号` 与关系网精确匹配的 Bot；不会从正文中的“Sirin”“莉芙”“莉莉”等名字猜测身份。没有唯一可信对象时面向全群。结构化生成异常时由 BotMesh 发送无专属称呼的全群兜底话题，不会再出现主动话题插件的“正文包含身份或称呼”测试失败。

因此 BotMesh 模式下，主动话题插件不会调用自己的 `llm_generate`，不会拼接关系 Prompt，不会添加称呼，也不会调用 `event.send` 或 `context.send_message`；它只调用一次 BotMesh 派发接口并记录成功或失败。

2.1.1 起，每次派发会生成统一 `trace_id`，并在主动话题、桥接层、BotMesh 集成入口和 BotMesh 派发器
的日志中逐段输出调用链。可据此核对实际加载模块、Persona 指纹、可信目标、关系方向、称呼和发送路由。

如果 BotMesh 已安装但尚未加载、身份不一致、配置错误或无法生成签名展示帧，本次主动消息会失败并稍后重试；不会回退到另一套 Persona，也不会发送可能触发 Bot 循环的普通正文。

如果保留了 BotMesh 文件但希望主动话题完全使用原生 Persona，请显式设置：

```text
botmesh_compat_enabled=false
```

## 群内命令

以下命令都只作用于接收命令的当前 Bot 和当前群：

```text
/主动话题 开启
/主动话题 关闭
/主动话题 状态
/主动话题 诊断
/主动话题 频率 低|中|高
/主动话题 间隔 120 300
/主动话题 上限 3
/主动话题 冷却 90
/主动话题 沉默 30
/主动话题 概率 70
/主动话题 时段 09:00 22:30
/主动话题 固定 09:00,21:30
/主动话题 固定 关闭
/主动话题 测试
/主动话题 重置
```

`/主动话题 诊断` 不调用模型也不发送消息，只显示当前平台/Bot/群身份、Persona 来源、BotMesh `bot_id`、逻辑群、有效 Persona 作用域与指纹，以及精确称呼条目数，用来区分 Persona 选错与称呼映射错误。

修改命令只允许 AstrBot 管理员、群主和群管理员使用。QQ 官方事件通常不携带可靠的群角色字段，因此默认允许 QQ 官方群成员管理本群设置；可用 `allow_qq_official_members=false` 关闭。状态和帮助允许普通成员查看。

## 频率预设

- 低频：随机间隔 240–480 分钟，每日最多 2 次，冷却 180 分钟，沉默 45 分钟。
- 中频：随机间隔 120–300 分钟，每日最多 3 次，冷却 90 分钟，沉默 30 分钟。
- 高频：随机间隔 60–120 分钟，每日最多 5 次，冷却 45 分钟，沉默 15 分钟。

使用间隔、上限、冷却、沉默或概率命令后，该作用域显示为“自定义”。

## 调度规则

自动消息必须同时满足：

1. 插件总开关和当前 Bot/群开关均开启。
2. 当前处于允许时段。
3. 当日成功发送数未达到上限。
4. 已超过上次成功发送后的冷却时间。
5. 群聊已沉默到设定阈值。
6. 固定时间位于宽限窗口内，或随机候选时间到达并通过概率判断。
7. 当前 Bot 的 Persona、发送路由和可选 BotMesh 身份均能唯一确认。

随机候选只在初始化、成功发送或概率未命中时重新抽取，不会每分钟连续抽签。失败只设置重试门槛，不计入每日数量，也不写入近期话题。

## 重启与发送路由

- 如果 UMO 首段就是唯一平台 ID，插件可以在重启后使用持久化路由主动发送。
- 如果 UMO 首段只是 `aiocqhttp` 等适配器类型，或平台是 `qq_official`/`qqofficial`，重启后必须先收到当前 Bot 的一条新群事件；在此之前只跳过，不猜测发送账号。
- 最近 `AstrMessageEvent` 只保存在内存中；持久化文件不会序列化平台事件对象。

## 状态文件

默认路径：

```text
data/plugin_data/astrbot_plugin_proactive_topics/state.json
```

v3 状态按稳定的内部作用域 ID 保存：

- `identity`：平台 ID、适配器类型、Bot 账号、原始群号；
- `route`：AstrBot UMO 和群名；
- `settings`：开关与调度配置；
- `runtime`：活动时间、成功计数、固定任务完成标记、近期上下文和失败重试门槛。

状态通过同目录临时文件写入并原子替换，避免进程中断留下半个 JSON。
